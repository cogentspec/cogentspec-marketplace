# Connect the AI to the GPTWeb work area

Applies only to `$gptweb`. ClaudeWeb, Snap, Desk and Qwen retain their own procedures and runtime. The installed Windows helper is unchanged.

The user completes **Set up GPTWeb** once on their computer. This installs the verified background helper from the CogentSpec Git marketplace. Computer setup and the helper's page acknowledgement are prerequisites; neither may turn the AI connection green. The user sends the complete copied `$gptweb` command to the intended AI conversation to authorize the following connection to that exact work area.

Use ordinary HTTPS reads from the AI session. Do not use browser control or request a Windows execution connection. Do not install a plugin, open a tab, select a project, run a Windows installer or transfer ownership. A Linux AI execution host can use this HTTPS project interface; it does not need to execute anything on the user's Windows PC.

Use a tool that makes a fresh HTTPS request and returns the response body. If a search-based web reader cannot retrieve these private live URLs or returns a cached response, use an existing HTTP client in the AI session's own execution environment, such as `curl` or Python's `urllib.request`. Linux execution is sufficient. This runs an HTTPS client in the AI sandbox, not software on the user's PC; do not ask for Windows execution or computer access. Do not install another tool or expose the private URLs in commentary. If no available tool can make a fresh HTTPS request, report that exact limitation and leave the connection unverified.

1. Read the exact private `/api/bridge/gptweb/ai/connect?request=...&grant=...` URL from the copied command. Do not construct a different work area or reuse a status-only verification link. If the helper is pending, report its message and let the user complete **Set up GPTWeb** in the existing work area. Retain the same URL and retry after setup; no second copy is needed merely because setup is pending.
2. For `project_read_required`, read the returned `projectReadUrl` with your HTTPS tool. This returns the current work area's authorized project or draft context. If it says `project_activity_required`, preserve that requirement; connection may finish, but project work requires the user to select or create a project in CogentSpec. Never infer or select one.
3. Read the returned `acknowledgeUrl`. It proves the work-area context was retrieved and acknowledges this AI session's protected exchange. Only a response with protocol `cogentspec-gptweb-ai-v1`, command `$gptweb`, status `connected`, `workspaceConnected:true` and `acknowledgementVerified:true` confirms success. Reading Git instructions, copying the command, downloading setup, a running helper, or reading the old status URL is not this exchange.
4. Retain the returned private `tools` URLs. Read `activity` at the start of every project instruction and after a pause. Use `changeHandoff` only for requested changes and `buildHandoff` only for an approved build request. These use the existing authoritative active-project, draft and contract checks. A changed selection requires a fresh handoff and clarification; connection does not authorize arbitrary file access, shell commands, project selection, publishing, deletion or protected setting changes.
5. A completed session remains authorized until its returned `expiresAt`, up to four hours and bounded by eight hours from the copied command's issue time. Moving focus, hiding the work area or normal idle time does not disconnect an acknowledged session. Continue using its existing project-interface URLs; recheck current activity before work without requesting another handshake merely because the AI paused. An unused command expires after fifteen minutes. After session expiry or an ownership/account change, report the exact message and require a fresh command from the intended work area. Page polling and helper heartbeats cannot create or renew AI authorization.

Keep capabilities, project context, credentials and handoff material private. Do not print connection URLs or claim the current ChatGPT browser conversation's identity has been independently attested: this protocol authenticates possession of the command the user supplied to this AI session. The green indicator requires its completed project-read exchange, current ownership, accepted computer and live helper. No proof means no green.
