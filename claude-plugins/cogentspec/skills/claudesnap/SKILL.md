# Open the CogentSpec Claude split-screen workspace

## User-command experience

A bare Bridge command is a connection request, not a debugging, audit or project-work request. Give one brief startup acknowledgement, perform the required checks privately, and finish with only this destination's prescribed short outcome and any required workspace link. Do not append a verification checklist, project names/counts, version/timing report, proof screenshot or CPD commentary unless the user asks or the host requires it.

Keep the normal current-package command within a one-minute interaction budget (or the destination helper's existing bounded budget). Go directly through its one-shot update/context/start/open/verify flow. Do not search repositories or chat history, run tests, collect optional diagnostics, reload unrelated skills, generate evidence files or rearrange windows. Reuse the already claimed intended browser when available; still live-claim it before navigation. Browser-tool destinations still require matching context, consumed handoff, visible **Bridge connected**, and an authorized **My projects** view; do not select or modify a project.

Interrupt only for a required permission/account approval, ambiguous destination, a verified update, unavailable update check, or failure. Announce a required update briefly and continue the same command. On failure, give the plain user message and supported next action; stop without automatic retries or destination substitution. A ready worker or accepted open is not a verified connection. Keep all existing integrity, privacy, authorization and destination-specific gates. Distinguish partial readiness honestly. Detailed diagnostics are a separate, explicit user request.

If a helper returns `licence_required`, show its plain `userMessage` and stop: this account needs an active CogentSpec licence (an enabled, eligible owner licence counts). Do not start installation, reconnect, computer approval, another command, or a workspace open. Preserve the saved credential. If it returns `licence_verification_unavailable`, report that access could not be checked; do not claim the licence is missing or start approval. A missing credential alone does not prove a missing licence; retain the documented first-time account/device authorization flow only for genuinely unidentified or revoked connections.

`$claudesnap` connects the main Claude Desktop window beside an external CogentSpec browser; it does not create a Claude Popout. This connection-only flow is self-contained; consult `../cogentspec/SKILL.md` only for separately requested project actions. It replaces the generic link-only sequence. Use `${CLAUDE_PLUGIN_ROOT}` for bundled scripts and run them from the invoking Claude project directory, never the cache, marketplace, home or temporary root. A normal Claude chat without plugin/local helper access cannot perform this connection. Use the host-approved Windows-user execution scope; never bypass required approval or expose protected credentials. If an update was already verified, use only its refreshed plugin root without repeating it. On any non-ready result, show its plain `userMessage` and supported recovery only, then stop; do not run another command or approval automatically.

1. Run `${CLAUDE_PLUGIN_ROOT}\skills\cogentspec\scripts\project-context.ps1` exactly once and require an isolated context. If a package update was already verified, use only the refreshed plugin root.

2. Invoke `${CLAUDE_PLUGIN_ROOT}\skills\cogentspec\scripts\start-cogentstack-bridge.ps1 -ContextKey <resolved context> -Surface claude-desktop -Experience split-screen` exactly once.
3. Require `status: ready`, the matching isolated context, `presenceVerified: true`, `accountState: signed_in`, `projectDataConnection: authenticated_desktop_bridge`, `mcpState: not_required`, `defaultDirectoryReady: true`, and `browserOpened: false`.
4. Validate `workspaceUrl` equals `webWorkspaceUrl`, has origin `https://cogentspec.app` and path `/stack`, and contains the resolved context, `surface=claude-desktop`, `experience=split-screen`, `open=web`, a fresh nav and complete `#desktop-web=cgw_...` handoff. Keep private links out of commentary, logs, clipboard and files.
5. Use the external browser window the user has snapped beside the main Claude Desktop. Inspect and live-claim its intended CogentSpec tab, then bind it as `claudeSnapTab`. Require `browserNavigationProtocol: cogentspec-claudesnap-navigation-v1` and execute the returned `browserNavigationCode` verbatim once as a browser-tool argument. It is the JSON-quoted `await claudeSnapTab.goto(...);` call for the validated handoff. This authorised tool argument may contain the one-use link; never echo it as diagnostic output or move it through a clipboard, local server, temporary file or Windows address-bar typing. If multiple external CogentSpec tabs make the target ambiguous, ask which one. If no external workspace exists, open one tab in the user-identified external browser. **Never use `open_in_codex` or an in-app browser pane for `$claudesnap`.** Do not substitute `$claudedesk`, `$claudeweb` or a GPT destination.
6. Verify that same external tab has the returned project context, `experience=split-screen`, a consumed handoff fragment, and a visible **Bridge connected** indicator. Check **My projects** loads without an authorization or missing-context error; an empty authorized library is valid. Only then say **CogentSpec Claude split-screen workspace is connected in your external browser.** If navigation is accepted but verification fails, report the observed state and stop without generating another handoff. Popout fields including `currentConversationConnected: false` do not apply here; do not inspect, open, pin or hide a Popout.
7. If browser control is unavailable, return the unconsumed `workspaceUrl` once as `[Open CogentSpec Claude split-screen workspace](<URL>)` and explicitly ask the user to open it in the right-hand external browser. Report only Bridge readiness until that page is verified. Never fall back to an embedded browser.

Help explains launching Claude Desktop, resizing it to fit, and **Win + Left/Right arrow** to snap each window. Physical snapping is user-controlled; Bridge readiness and an accepted browser open do not prove the split is arranged. Keep `$claudedesk` and `$claudeweb` as separate destinations; never inspect Claude's private conversation UI.
